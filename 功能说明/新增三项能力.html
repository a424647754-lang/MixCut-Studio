从「按节奏切」到「按句子切」
以及顺手补掉的两个老问题

这一轮把 Super Director 里几件真正有用的东西拆出来装进 MixCut：语音转写驱动的整句切割、 CUDA 指纹查重，以及一个外置 CUDA 引擎桥。全部默认关闭，勾了才跑。

01

整句切割

默认关闭
解决什么
口播、访谈、Vlog 素材上，纯按节奏取片经常把一句话从中间剪断，成片听着"话被切掉了"。
怎么做
先对素材做一次语音转写拿到整句时间轴，再让混剪把随机算出的长度吸附到最近的句尾—— 只在「最短/最长片段」和剩余时长允许的区间里找边界，不会为了整句把节奏改乱。
效果
同一素材同一随机种子实测：切点离句尾的最大偏差从 1.37s 降到 0.11s。
代价
首次要转写，28 秒素材约 3.5 秒（small 模型、CPU）。结果按素材路径缓存，第二次直接命中。
02

指纹查重

默认关闭
解决什么
素材池里混进同一条片子的重复拷贝（相册重复导出、另存版本），会在成片里来回重复同一段画面。
怎么做
每条素材用 CUDA 引擎提一次指纹（phash 关键帧 + 色彩直方图），在 Python 里直接比， 综合相似度 ≥ 0.92 判为重复；同组保留时长最长的一条，其余跳过并在日志里点名。
效果
同一文件的副本 1.000，完全不同素材 0.000，分组与保留项都正确。
代价
4K 素材提一次指纹约 2 分钟；指纹按路径缓存，只有新素材才提取。
03

CUDA 引擎桥

已就位
为什么
MixCut 用的是 pip 版 OpenCV（cv2 5.0.0），cv2.cuda 恒为 0 个设备， Python 侧拿不到 GPU 算子。所以 GPU 活儿交给外置引擎，不重建 cv2。
是什么
Super Director 的两个 exe：sd_asr.exe（转写）、sd_dedup.exe（CUDA 提指纹）， 用 CUDA 13.5 + OpenCV CUDA 模块编译。
怎么找
环境变量 MIXCUT_GPU_ENGINE → 项目内 engine/bin → 本机安装位置。找不到就安静降级，照常出片。
# 自检输出（本机实测）
engine: {"available": true, "dir": "D:\超级导演\cpp\build\bin",
         "exe": {"sd_asr.exe": true, "sd_dedup.exe": true}}

# 转写
ok=True 转写完成：1 句  用时 3.5s
# 查重
同一片子 1.000 · 不同片子 0.000 · 分组 [["10月26日.mp4", "dup_test.mp4"]]
04

改了哪些文件

文件改动
mixcut/gpu_engine.py 新增。引擎定位、转写、指纹、缓存（名字 + 路径摘要，防同名撞车）
mixcut/sentence_cut.py 新增。整句边界提取、切点吸附、起点吸附
mixcut/audio_dedup.py 新增。指纹相似度、重复分组、保留策略
mixcut/workers.py 分析之后插入「查重 → 转写」两步，带进度与取消检查点
mixcut/mixbuilder.py 取片时对起点与切点各做一次吸附，受最短/最长片段约束
main.py 混剪参数区加两个开关，勾选状态传进检测/混剪选项

说清楚没做到的

  • OpenCLIP 还跑在 CPU：torch 2.15.0+cpu，cuda_available=False。要 GPU 得装 cp314 的 CUDA 版 torch，另需确认权重对应的模型结构。
  • OpenCLIP 只适合「文字检索素材」「画面风格相似度」，不做"这段话有没有价值"这类内容判断。
  • 转写只覆盖有人声的素材；纯音乐/环境音素材会跳过整句吸附，按原节奏切。
  • 查重只看画面与时长特征，剪得很像但内容不同的两条片子可能漏判，阈值可按需调整。
  • 两个开关默认关闭，不勾选时流程与之前完全一致。
